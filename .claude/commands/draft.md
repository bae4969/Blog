# /project:draft

모호한 요청을 사용자와의 짧은 라운드 대화로 다듬어 `/full`에 넘길 한 줄 요청으로 조립하는 슬래시 커맨드.

이 prefix가 붙으면 메인이 사용자 원문에서 의도·범위·완료 조건·제약을 점진적으로 끌어내고, 충분해졌다고 사용자가 판단하는 시점에 한 줄 요청으로 조립해 `/full`(메인이 [`.claude/rules/main_full_procedure.md`](.claude/rules/main_full_procedure.md) 따름)로 진입한다.

## 언제 쓰나

- 사용자 요청이 모호해 무엇을 바꿔야 하는지 단번에 잡히지 않을 때
- 변경 범위·대상 파일이 불명확해 `/full` 직행이 부담스러울 때
- 의도부터 정리하고 옵션을 좁힌 뒤 본격 사이클로 넘기고 싶을 때
- 같은 요청을 여러 번 명확화해야 할 가능성이 있을 때

## 실행 절차

### 0단계 — 점유 확인

`.claude/state/current.json`을 먼저 Read한다.

- `status`가 `searching` / `planning` / `awaiting_approval` / `implementing` / `verifying` / `blocked` → 본 커맨드 진입을 보류하고 재개 카드(workflow_4stage.md "세션 재개") 우선 실행.
- 비어 있거나 `done` / `aborted` → 1단계로.

### 1단계 — 원문 보존

사용자 메시지에서 `/draft` prefix만 제거하고 나머지 본문을 그대로 보존한다. 원문은 마지막 조립 단계까지 가공하지 않고 가지고 간다.

### 2단계 — 라운드 반복 (사용자가 끊을 때까지)

각 라운드에서 메인이 다음을 수행한다:

1. 현재까지 파악된 의도를 토대로 모호 지점을 **목표·범위·완료 조건·제약** 4범주 중에서 최대 3개까지 추출한다.
2. AskUserQuestion 한 호출에 다음을 묶어 띄운다 (총 카드 ≤4, 베이스 한도):
   - 모호 지점 카드 ≤3개 (각 카드에 메인의 1차 추측을 Recommended 옵션으로 포함)
   - 진행 제어 카드 1개 — 옵션: "충분함 / 한 라운드 더 / 취소"
3. 응답을 `temp/progress.md`에 `## draft round N` 헤더로 append한다.
4. 진행 제어 응답에 따라 분기:
   - **충분함** → 3단계로.
   - **한 라운드 더** → 다음 라운드 반복.
   - **취소** → 메인이 history write(`status=aborted`) 후 종료.

라운드 수는 **무한**이다. **하드 캡 없음** — 사용자가 "충분함" 또는 "취소"를 명시할 때까지 묻는다. 라운드가 5·10을 넘어도 메인이 자동 종료하거나 휴리스틱으로 끊지 않는다.

### 3단계 — 한 줄 요청 조립 + 확인

누적된 응답과 원문을 합쳐 한 줄 요청으로 조립한다. 채팅에 조립 결과를 표시하고 AskUserQuestion 확인 카드를 띄운다 — 옵션:

- **이대로 /full 시작** (Recommended)
- **더 다듬기 (라운드 추가)** → 2단계로 복귀, 라운드 카운터 유지
- **취소** → 메인이 history write(`status=aborted`) 후 종료

### 4단계 — full 진입

승인 응답이 오면 메인이:

1. `.claude/state/current.json`을 `mode=full`로 초기화하고 `request` 필드에 조립된 한 줄 요청을 기록.
2. [`main_full_procedure.md`](.claude/rules/main_full_procedure.md) Phase 1(서칭)부터 시작.

자동 진입 금지 — 반드시 사용자가 확인 카드에 응답한 뒤에만 진입한다.

## 예시

```
/draft 이거 좀 어떻게 해줘
```

→ 라운드 1: 카드 3개(대상 모듈 / 원하는 결과 / 진행 제어) 띄움.
→ 사용자가 "한 라운드 더" 선택, 대상은 인증 모듈, 원하는 결과는 토큰 만료 처리.
→ 라운드 2: 카드 3개(만료 후 동작 / 회귀 테스트 범위 / 진행 제어) 띄움.
→ 사용자가 "충분함" 선택.
→ 조립: "인증 모듈의 토큰 만료 시 자동 재발급 흐름을 구현하고 회귀 테스트 추가" 표시 + 확인 카드.
→ "이대로 /full 시작" 응답 → `/full <조립된 요청>`으로 진입.

## 안전장치

- 라운드 수 **제한 없음** — 사용자의 "충분함"·"취소" 응답만이 종료 신호. 메인 휴리스틱 종료 금지.
- 한 라운드 AskUserQuestion 카드 묶음 ≤4 (베이스 한도 준수).
- 확정 후 `/full` 진입은 **사용자 확인 카드 응답 후에만**. 자동 모드 승격 금지.
- `.claude/state/current.json`이 in-progress·blocked면 본 커맨드 보류, 재개 흐름 우선.
- 모드 결정 prefix 매칭 원칙([`main_full_procedure.md`](.claude/rules/main_full_procedure.md) §1) 준수: `/draft` 자체가 prefix, full 전환도 사용자 명시 응답으로만.
- `.git/`, `.claude/state/`, `.claude/settings.local.json`, lock 파일, CI 설정은 변경하지 않는다. 본 커맨드는 `temp/progress.md` append와 `.claude/state/current.json` 초기화(승인 시)만 수행한다.

## 설계 원칙 (이 커맨드가 따르는 것)

- **묻기 전에 추측한다** — 무작정 질문 폭격이 아니라 모호 지점만 카드로 묶고 각 카드에 1차 추측을 Recommended로 포함.
- **사용자가 종료 시점 결정** — 휴리스틱 자동 종료 없음, 라운드 캡 없음. 끝낼 시점은 사용자가 안다.
- **확정 → 1회 확인 → 진입** — 조립 직후 자동 진입 금지, 확인 카드 응답 후에만 `/full`로 넘어간다.
- **재진입 안전** — current.json 점유 시 양보, 재개 흐름이 우선이다.
