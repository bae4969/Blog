# 계획 체크리스트 흐름 — 원문요청 → 승인 → 진행 → 검증 → 요약

이 베이스의 기본 작업 흐름은 다음 여섯 단계다:

**원문요청 → 계획 체크리스트 → 사용자 승인 → 계획 진행 → 실행 검증 → 요약**

서브에이전트(planner)나 고정 4단계는 없지만, 실제 변경이 필요한 작업은 바로 손대지 않는다. 메인이 계획을 체크리스트로 세워 **사용자 승인을 받은 뒤** 실행하고, 실행 결과를 검증해 요약한다 — 서브에이전트 검증 안전망이 없는 대신, 실행 전에 방향을 사용자와 맞춘다.

## 언제 이 흐름을 타나

- **탄다**: 파일을 만들거나 고치는 등 **실제 변경이 일어나는 작업**.
- **생략한다**: 순수 조회·질의·설명(변경 없음)은 즉시 답한다. 자명한 1줄 수정(typo 등)은 판단해서 생략할 수 있다([coding_principles.md](coding_principles.md) Tradeoff). **애매하면 흐름을 타는 쪽**(안전한 쪽)으로.

## 1. 원문요청

사용자 요청을 접수한다. 모호하면 여기서 먼저 묻는다([coding_principles.md](coding_principles.md) §1). 위치를 모르면 Read/Grep/Glob으로 관련 코드를 먼저 찾아 계획의 근거로 삼는다. **사용자 원문의 의도·강도·뉘앙스를 다음 단계로 그대로 들고 간다** — 계획 체크리스트가 원문을 요약하며 뜻이 흐려지지 않게.

## 2. 계획 체크리스트

무엇을 어떤 순서로 할지 **체크리스트**로 정리한다. 각 항목은 검증 가능한 형태로:

```
## 계획: <요청 한 줄 요약>

영향 파일: <경로들>
리스크·주의: <있으면>

- [ ] 1. <할 일> → 검증: <완료를 어떻게 확인하나>
- [ ] 2. <할 일> → 검증: <...>
- [ ] 3. <할 일> → 검증: <...>
```

- 항목은 대략 3~7개. 너무 잘게 쪼개지 않는다.
- 선택지가 갈리면 계획 안에서 옵션으로 제시한다([coding_principles.md](coding_principles.md) §1).

## 3. 사용자 승인 (게이트)

체크리스트를 사용자에게 보여주고 승인받는다. **승인 없이는 4단계(진행)로 넘어가지 않는다.**

- 승인 옵션: **이대로 진행 / 수정요청 / 취소**. AskUserQuestion 도구가 있으면 카드로, 없으면 텍스트로 명확히 묻는다.
- 방향이 갈리는 선택지가 있으면 그 선택도 같이 묻는다 — 추천안을 맨 앞에 두고 이유를 한 줄 붙인다.
- **수정요청**이면 체크리스트를 고쳐 다시 승인받는다. **취소**면 멈춘다.
- 설명은 사용자 언어로. 내부 용어 대신 "무엇을 하면 무슨 결과가 되는지"로.

## 4. 계획 진행 (실행)

승인된 체크리스트를 항목별로 수행한다:

- 항목을 순서대로 Edit/Write로 처리하고, 끝낸 항목은 체크한다. 진행 상황은 TodoWrite로 보여도 좋다.
- 코드 변경에는 [coding_principles.md](coding_principles.md) 3원칙을 적용한다 — 승인된 계획 범위 안에서.
- **계획과 어긋나기 시작하면 멈춘다.** 실행 중 새 사실을 발견해 계획을 바꿔야 하면, 바꾼 계획을 **3단계(승인)로 되돌려** 다시 확인한 뒤 잇는다(조용히 방향을 틀지 않는다).

## 5. 실행 검증

실행 결과가 요청을 충족하는지 검증한다:

- 각 체크리스트 항목의 검증 방법으로 확인한다. 테스트·빌드가 있으면 Bash로 돌리고, 없으면 사용자가 확인할 체크리스트를 남긴다([coding_principles.md](coding_principles.md) §3).
- 과복잡하거나 계획에 없던 곁가지 변경을 스스로 결함으로 잡는다(§2).
- 검증 실패면 원인을 고쳐 다시 실행·검증한다. 방향 자체가 틀렸으면 3단계(승인)로 되돌린다.

## 6. 요약

체크리스트 대비 **한 일 + 검증 결과**를 요지로 보고한다.

- 각 항목이 어떻게 됐는지(완료/부분/건너뜀), 무엇으로 검증했는지.
- 자동 검증 수단이 없으면 사용자가 확인할 체크리스트를 남긴다.
- 긴 본문은 `temp/output/`에, 채팅엔 요지·링크만(temp/ 하위 폴더 구분은 [CLAUDE.md](../../CLAUDE.md) "temp/ 규약" 참조).
