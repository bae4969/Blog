# git 이력으로 세션 맥락 잡기

이 베이스는 무거운 상태 파일(`current.json`)·history 폴더·Stop 훅을 두지 않는다. 그 대신 **git 이력이 "직전까지 무슨 작업을 했는지"의 진실의 원천(SoT)**이다 — 커밋이 곧 작업 이력이다.

## 세션 시작 절차

새 세션이거나 맥락이 필요할 때, 메인은 요청을 처리하기 전에 git 이력을 먼저 읽는다:

1. `git log --oneline -10` — 최근 작업 흐름 파악. 필요하면 범위를 늘리거나 `git log -p <커밋>`으로 특정 커밋을 상세히 본다.
2. `git status` — 커밋 안 된 변경(작업하다 만 흔적)이 있는지.
3. `git diff` — 커밋 안 된 변경이 있으면 무엇을 하다 말았는지.

이걸로 "이 프로젝트가 지금 어디까지 와 있고, 직전에 뭘 하다 멈췄는지"를 파악한 뒤 사용자 요청을 처리한다.

## 진행 중이던 작업이 보이면

`git status`에 커밋 안 된 변경이 남아 있으면, 이전 세션이 작업하다 끊긴 것일 수 있다. 새 요청을 바로 덮지 말고 **한 줄로 확인**한다 — "이어서 마무리할까요, 아니면 새 작업으로 갈까요?" (선택지 카드를 쓸 수 있으면 카드로.)

## git이 없는 디렉토리

`git rev-parse`(또는 `git status`)가 실패하면 미초기화 디렉토리다 — 이력 확인은 건너뛴다. 이력 추적이 유용해 보이면 사용자에게 `git init`을 **제안**하되, 동의 없이 초기화하지 않는다.

## 커밋은 사용자 결정 (읽기 전용 사용)

이 베이스는 git 이력을 **읽기 전용**으로 쓴다 — 맥락 파악용으로 `log`/`status`/`diff`를 볼 뿐, **커밋·푸시는 사용자가 요청할 때만** 한다. 자동으로 커밋하지 않는다.

- 커밋을 요청받으면 관련 변경끼리 **기능별로 나눠** 커밋한다.
- 커밋 메시지에 'Claude가 작성함'을 나타내는 문구를 넣지 않는다.

## git 확인은 CLI로

git 이력 확인은 브라우저·웹 UI가 아니라 `git` CLI로 한다. 한글 커밋 메시지가 깨지면 `git -c i18n.logOutputEncoding=UTF-8 log`를 쓴다(Windows PowerShell에서는 `[Console]::OutputEncoding=[Text.Encoding]::UTF8` 병행).
