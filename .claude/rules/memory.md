# memory — 읽기·쓰기

`.claude/memory/`는 **코드·git 이력이 말해주지 않는 사실**을 담는다. `rules/`가 "~해라"라면 memory는 "~이다"다.

## 읽기 — 인덱스는 자동으로 오지만 개별 파일은 아니다

`.claude/rules/`는 Claude Code가 `rules/**/*.md`를 전부 자동 로딩하지만, **`.claude/memory/`에는 그런 기전이 없다.** 그래서:

- `CLAUDE.md`의 `@.claude/memory/MEMORY.md` import가 **인덱스만** 싣는다.
- 인덱스 안의 `- [제목](파일.md)`은 **마크다운 링크라 import가 아니다** — 개별 memory 파일은 컨텍스트에 없다. **훅을 보고 직접 Read해야 한다.**
- 읽는 시점: ⓐ 세션 시작 맥락 파악 때(`git log`/`git status`와 나란히), ⓑ 작업 중 훅이 걸리는 주제를 만났을 때.
- **훅이 애매하면 읽는 쪽으로.** 한 줄 요약만으로 관련성을 판단하기 어렵다. 안 읽어서 놓치는 비용이 읽어서 낭비하는 비용보다 크다.
- memory는 **시점 기록**이라 코드와 어긋날 수 있다. 파일·함수·플래그를 지목하는 내용이면 현재 코드로 확인한 뒤 사실로 말한다.
- 실제로 무엇이 실렸는지 확인하려면 `/context`.

## 쓰기

알아둘 사실이 생기면 `.claude/memory/`에 **한 파일 = 한 주제**로 적고 `MEMORY.md`에 한 줄 건다.

```markdown
---
name: <kebab-case-슬러그>
description: <한 줄 요약 — 관련성 판단에 쓰인다>
metadata:
  type: project | reference
---

<사실. 관련 memory는 [슬러그](슬러그.md)로 링크.>
```

- 인덱스 형식: `- [제목](파일명.md) — 한 줄 훅`. **훅이 곧 로딩 관문**이다 — 이 한 줄만 보고 읽을지 정하므로 무엇에 대한 사실인지 구체적으로 쓴다.
- `MEMORY.md`에는 **인덱스만**. 본문을 인덱스에 쓰지 않는다.
- **코드·git으로 알 수 있는 것**(디렉토리 구조·커밋 이력·과거 수정 내역)은 쓰지 않는다. 그건 `git log`가 SoT다([git_history.md](git_history.md)).
- 틀린 것으로 밝혀진 memory는 지운다. 사실이 바뀌면 새 파일을 만들지 말고 기존 파일을 고친다.
- 내장 auto memory(`~/.claude/projects/...`)는 `.claude/settings.json`의 `{"autoMemoryEnabled": false}`로 꺼져 있다 — 그 경로는 머신 로컬이라 git으로 따라오지 않는다. memory는 **이 폴더에** 둬서 프로젝트와 함께 이동시킨다.

**Why:** `.claude/memory/`는 `rules/`를 흉내 내 만든 폴더인데 Claude Code에 자동 로딩 기전이 없다. "적어뒀는데 아무도 안 읽는" 일이 **구조적으로** 발생하므로, 읽으라는 지시가 **자동 로딩되는 `rules/` 안에** 있어야 도달한다 — 이 파일이 `memory/`가 아니라 `rules/`에 있는 이유다.
